# Antigravity との連携

Claude Code(クラウド)と Antigravity(Mac)に別々の仕事を割り当て、
リポジトリを受け渡しの場にして一貫した流れを作る。

## なぜ 2 つ使い分けるのか

どちらも「エージェントに仕事をさせる」道具だが、**できることが違う**。

| | Claude Code(クラウド) | Antigravity(Mac) |
|---|---|---|
| 動く場所 | Anthropic 側の環境 | 手元の Mac |
| 無人で動くか | **動く**(5 時間ごとに自動) | 起動して走らせたときだけ |
| ブラウザ操作 | できない | **できる**(Chrome 拡張で画面を操作) |
| 使うモデル | Claude | Gemini 3 ほか |

決定的なのは**ブラウザ操作**の一点。

Google AI Pro は Gemini アプリと Flow を使う権利であって、**API アクセスを含まない**。
つまり Veo での動画生成は、画面を人が操作するしか方法がない。
Antigravity のブラウザ制御は、ここを埋められる唯一の手段になる。

逆に、無人で回り続ける必要がある部分(合議、解析、検証の判定)は
Mac の電源に依存しないクラウド側に置く。

## 流れ

```
[クラウド] 合議が「何を検証すべきか」を決める
              ↓
[クラウド] カット表からプロンプトを取り出し、依頼票を work/queue/ に置く
              ↓  (git)
[Mac] Antigravity が依頼票を読み、Flow をブラウザ操作して生成、動画を置いて commit
              ↓  (git)
[クラウド] 生成物を参照と同じ解析に通し、項目ごとに比較してレポートを書く
              ↓
[クラウド] 次の合議が検証結果を読んで、次に何をするか決める
```

**両者は直接やり取りしない。** git だけが共有面になっている。片方が止まっていても
もう片方は動けるし、どちらが何をしたかがコミット履歴に残る。

## 準備

### 1. Antigravity にこのリポジトリを開かせる

`makeamoney` フォルダをワークスペースとして開く。ルートに `AGENTS.md` があり、
Antigravity はこれを読んで分担と禁止事項を把握する。

### 2. ブラウザ拡張を入れる

Antigravity のエージェントが初めてブラウザを使うとき、Chrome 拡張の導入を求められる。
許可すると、以降は画面操作ができるようになる。

### 3. エージェントに依頼する

Agent Manager で、こう頼む。

> work/queue の依頼票を順に処理して。AGENTS.md の手順どおりに。

依頼票の形式・保存先・失敗したときの扱いは `AGENTS.md` に書いてあるので、
毎回説明する必要はない。

## 依頼票を作る

```bash
python3 tools/make_worksheet.py out/xxx/cutsheet.json
```

`work/queue/` に生成依頼が積まれる。同時に `verify/worksheet.html` もできるので、
**自分で Flow を操作したい場合はそちらを使えばよい**(Antigravity は使わなくてもよい)。

## 検証する

Antigravity が動画を置いて push したら、クラウド側で:

```bash
bash app/verify.sh out/xxx
```

参照と生成を項目ごとに比べたレポートが `out/xxx/verify/report.html` に出る。
判定基準は `README.md` の「生成AIで再現できているかを検証する」を参照。

## 分かった上で使うべきこと

**ブラウザ操作は壊れやすい。** Flow の画面が変われば手順は通らなくなる。
失敗したら `work/failed/` に理由が残るので、そこを見て `AGENTS.md` の手順を直す。
自動化できたと思って放置すると、静かに止まる。

**Google の利用規約を確認しておくこと。** 消費者向けの画面を自動操作することが
規約上どう扱われるかは、Google の定めによる。自分のアカウントで自分の作業を
自動化する範囲であっても、事前に確認しておくほうがよい。

**Mac が要る部分は残る。** Antigravity はデスクトップアプリなので、この工程だけは
PC の電源が要る。API が提供されない以上ここは避けられない。裏を返すと、
**それ以外はすべてクラウド側で完結している**。

## 将来、単純になる可能性

Google が Veo の API アクセスを AI Pro に含めるか、従量課金の API を使う判断をすれば、
ブラウザ操作は不要になり、生成もクラウド側に移せる。そうなれば Mac は完全に不要になる。

その場合に差し替えるのは `work/queue` を消費する部分だけで、依頼票の形式・検証・
合議はそのまま使える。分担を git 越しにしてあるのは、この差し替えを楽にするため。
